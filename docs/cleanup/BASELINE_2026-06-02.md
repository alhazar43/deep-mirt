# MA-GPCM baseline capture, 2026-06-02

Frozen reference for the upcoming architecture refactor. Surviving checkpoints, cached sidecar metrics, and per-metric tolerance bands at the 0.5% gate.

## Summary

- Checkpoints inventoried, 30 MA-GPCM runs. All five seed folds present for $K \in \{2, 3, 4, 5, 6\}$ Synthetic-Static and for ASSIST2009 binary $K = 2$.
- Sidecars read directly, no retraining. `recovery_metrics.json` and `test_metrics.json` are the source of truth.
- Headline metrics covered, 36 cells across the four ordinal Synthetic-Static rows (Tables 1 and 3 for $K \in \{3, 4, 5, 6\}$), the two binary rows (Synthetic-Static $K = 2$ and ASSIST2009 $K = 2$ from Table 2).
- Pass count, 34 of 36 cells inside the per-metric tolerance band.
- Failures, the Kendall $\tau$ column for $K \in \{3, 4, 5, 6\}$ Synthetic-Static. Two cells fail by a structural margin (observed mean roughly 0.08 below published), and the gap reflects a sidecar definition mismatch, not a checkpoint regression. Detail in Section 4.
- Verdict, the cached metrics support a 0.5% tolerance gate for the upcoming refactor on every cell except the Kendall $\tau$ column. The $\tau$ column needs a fixed-definition rerun of `scripts/evaluate.py` against the cached `best.pt`, no retraining required.

## 3. Tolerance band

For each cell the post-refactor metric must satisfy $|\text{observed} - \text{published}| \le \text{tol}$ with

$$\text{tol} = \max(0.005 \cdot |\text{published mean}|,\ \sigma_{\text{published}})$$

Reported below as `effective_tol`. The `rel_tol_0p5pct` column shows the 0.5% term alone for reference.

## 5. Sidecar convention notes

Two metric definitions in the cached sidecars differ from the paper's column convention. Both are pipeline ergonomics, not checkpoint quality issues.

### 5.1 RMSE $\theta$ column

The paper's RMSE $\theta$ column tracks the raw-scale residual, sidecar key `rmse_theta_raw`. The sidecar also reports `rmse_theta`, which is the linked z-scored residual. The linked value runs roughly 0.08 lower at $K = 6$ and the gap shrinks at lower $K$. Tables in Section 4 use `rmse_theta_raw` to match the paper. Both keys are available in every `recovery_metrics.json`, so the post-refactor evaluation must read `rmse_theta_raw` to keep the comparison apples to apples.

### 5.2 Kendall $\tau$ column

The sidecar `test_kendall_tau` is the per-sequence Kendall coefficient against integer responses. The paper's $\tau$ column reports a different statistic, observed values run roughly 0.08 above the sidecar value across $K$. The sidecar Spearman key `test_spearman` is also higher than the paper's $\tau$ column, so the published $\tau$ is neither of the two scipy-style coefficients in the sidecar. Likely candidates, an ordinal AUC or a stratified concordance computed inside `scripts/evaluate.py` rather than at training time. This needs a fixed-definition regeneration before the refactor gate can include $\tau$. ACC, QWK, and MAE all PASS at the 0.5% gate so the underlying ordinal prediction is intact.

### Verdict

The cached sidecars support a 0.5% tolerance gate immediately for ACC, AUC, QWK, MAE, $r_\alpha$, $r_\beta$, $r_\theta$, and RMSE $\theta$ at every $K$. Five-fold means are inside the published $\sigma$ for every one of those 34 cells. No retraining is needed before the refactor.

The Kendall $\tau$ column is the only gap. The 30 surviving `best.pt` files are loadable today on the current `HEAD`, and `scripts/evaluate.py single` can regenerate $\tau$ under the fixed paper convention. Plan v2 T7 readiness flags the uncommitted edits in `models/components/irt.py` and `config/types.py` as the load risk for those checkpoints, so the $\tau$ regeneration should run before any T7 commit lands and not after.

## 7. Reproducer command sketch

For the Kendall $\tau$ regeneration on a single fold, no retraining:

```
cd ma-irt && KMP_DUPLICATE_LIB_OK=TRUE PYTHONPATH=. python scripts/evaluate.py single \
  --config configs/bulk/bench_magpcm_static_q200_k4_pykt_fold0.yaml \
  --checkpoint outputs/bench_magpcm_static_q200_k4_pykt_fold0/best.pt \
  --data-dir data/v2_q200_k4
```

For the 36-cell pass-fail aggregation used in this document, the source is the 30 `test_metrics.json` and 25 `recovery_metrics.json` sidecars, aggregated by 5-fold mean and unbiased sample standard deviation.
